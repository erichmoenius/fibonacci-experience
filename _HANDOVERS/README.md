# Fibonacci Experience — Handover Archive

This archive preserves project continuity between chats. GitHub is the version-controlled master; Google Drive is a manually maintained mirror. No automatic synchronization is configured.

## Layout

- CURRENT_STATE.md — latest verified handover and explicit knowledge gaps.
- ARCHIVE/ — dated, immutable historical handovers.
- TEMPLATES/SUCCESSOR_CHAT_TEMPLATE.md — checklist for preparing a successor chat.
- ARCHIVE/.gitkeep — empty placeholder because Git tracks files, not empty directories.

## Handover procedure

1. Recheck the intended repository, branch, commit and working-tree status.
2. Record the latest verified checkpoint, evidence, frozen systems, unresolved issues and next authorized step. Distinguish tested results, informed suggestions and experiments.
3. Before replacing CURRENT_STATE.md in future, preserve its previous version as ARCHIVE/HANDOVER_YYYY-MM-DD_NNN.md; never overwrite an archived handover.
4. Use the template to introduce the successor chat. Link the predecessor chat and exact source commit.
5. Update the Drive mirror explicitly after the GitHub version is accepted; compare contents and record the source revision. Resolve disagreements using verified Git history and evidence rather than file dates alone.

Prepare a handover after meaningful milestones and when context becomes difficult to track. There is no reliable live conversation-capacity meter or guaranteed advance warning.

## Boundaries

Fibonacci Experience is separate from Motion Lab and Darknet Lab. Preserve working architecture and checkpoints. Make one meaningful change, then observe and test. This archive does not authorize application edits, releases, deployment changes or account-setting changes.

The GitHub repository is public. Keep credentials, private account data and secrets out of all handovers.
